- **Standard 1 — Customer Data Encryption:** Customer data is stored unencrypted.

- **Standard 5 — Security Audit Logging:** Centralized security audit logs are not maintained despite the processing of customer data.

## Remediation

- **Standard 1 (Customer Data Encryption):** Implement data-at-rest encryption using AES-256 or an equivalent approved cryptographic standard for all stored customer information.
- **Standard 2 (Legacy Database Integration):** Refactor the data access architecture to interface with the legacy database via an approved secure REST API or service-based integration layer; remove direct database connections.
- **Standard 3 (Business Continuity and Disaster Recovery):** Formally determine and document the business criticality of the reporting system. If deemed a critical application, design and implement multi-region recovery capabilities.
- **Standard 4 (Centralized Identity and Access Management):** Integrate the application with the enterprise centralized identity provider (IdP) supporting role-based access control (RBAC), and eliminate local account authentication as the primary login mechanism.
- **Standard 5 (Security Audit Logging):** Implement automated, centralized audit log forwarding to capture all security-relevant events (e.g., authentication, access to customer data, privilege changes) into the enterprise logging system.
